# Physics-Aware Branched Mu-Map Ensembles

This repository accompanies Team TUM's BIC-MAC 2026 submission, described in
[`Physics_Aware_Branched.pdf`](Physics_Aware_Branched.pdf). The method predicts
a CT attenuation map from NAC-PET, an X-ray topogram, and Dixon MRI. PET is not
generated by this repository; the challenge organizers reconstructed PET from
the submitted CT with the official BIC-MAC pipeline.

Team TUM placed joint sixth and was selected as a Tier 1 team. On the hidden
20-subject test set, the final submission obtained:

| Metric | Value | Rank |
|---|---:|---:|
| CT mu-map MAE | 0.00591 | 10 |
| Whole-body SUV MAE | 0.0284 | 3 |
| Organ bias | 1.95% | 4 |
| Brain outlier score | 0.0249 | 8 |
| Mean rank | **6.25** | **joint 6** |

## Reproducibility release

This release follows the BIC-MAC organizers' request for participating teams to
open-source their inference code and, where possible, their training code. It is
reconstructed from the exact organizer-tested image
`bicmac-e582-e612:dry-run-20260810`, not from later research code. Its inference
sources are under [`src/champion`](src/champion), and the checkpoint manifest is
[`configs/runtime-closure.json`](configs/runtime-closure.json).

## Repository layout

```text
src/champion/              final inference implementation
configs/                   deployment and checkpoint manifests
training/source/champion/  training implementation snapshot
training/configs/          final model-family configurations
huggingface/               model card for the weight release
scripts/                   integrity and packaging utilities
tests/                     lightweight release checks
```

The 11 checkpoints are distributed separately because they total about 1.61 GB
uncompressed. They are prepared for release from
[`ziyuan-li/bic-mac-tum-e612`](https://huggingface.co/ziyuan-li/bic-mac-tum-e612).

## Environment

The final container used Python 3.12, PyTorch 2.10.0, CUDA 12.6.3, MONAI 1.5.2,
NiBabel 5.3.3, SciPy 1.18.0, and tqdm 4.67.3. Install a CUDA-compatible PyTorch
build first, then the remaining dependencies:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install torch==2.10.0
python -m pip install -r requirements.txt
```

The final system was evaluated on one NVIDIA A40 GPU. It performs 13 network
forwards using 11 unique checkpoints and is not intended for CPU inference.

## Weights

Download the model repository into `model/`:

```bash
hf download ziyuan-li/bic-mac-tum-e612 --local-dir model
python scripts/verify_weights.py --model-dir model
```

Every checkpoint and configuration file is checked against the byte count and
SHA-256 digest recorded in the final container. The expected directory layout
is documented in the Hugging Face model card.

## Inference

Each input directory must contain the four challenge feature files:

```text
nacpet.nii.gz
topogram.nii.gz
mri_combined_in_phase.nii.gz
mri_combined_out_phase.nii.gz
```

Run inference with:

```bash
PYTHONPATH=src python -m champion.predict \
  --features-dir /path/to/features \
  --model-dir model \
  --output-ct output/ct.nii.gz \
  --report output/runtime-report.json \
  --device cuda:0
```

The output is a NIfTI CT volume in Hounsfield units with the NAC-PET shape and
affine. The implementation uses 192 x 192 x 192 MONAI sliding windows with 25%
overlap. On the four released Validation subjects, organizer-measured A40
runtimes were 268.8, 270.1, 276.7, and 267.8 seconds.

To rebuild the challenge-style container after downloading the weights:

```bash
docker build -f docker/Dockerfile -t bicmac-tum:e612 .
docker run --rm --gpus all --network none \
  -v /path/to/features:/data/features:ro \
  -v /path/to/output:/data/output \
  bicmac-tum:e612
```

The Dockerfile pins the exact PyTorch base-image digest used by the submitted
container. The output mount may contain organizer-owned files such as
`run.log`; the final compatibility entrypoint does not reject them.

## Training

The training snapshot and the final family configurations are described in
[`training/README.md`](training/README.md). The code covers cache preparation,
base-network training, and MRI-conditioned refiner training. Exact checkpoint
reproduction requires the same multi-stage initialization chain and stochastic
training environment; the released inference path and weights are the canonical
reproducibility target.
